# 权限模型

## 原则

1. **按发送者判权**：会话不携带权限；每条消息按 `sender_id` 决定档位。群里即使是管理员，也只落 `owner-group`（禁写禁执行）。
2. **纵深防御**：准入策略（有没有资格）→ 档位 → 工具白名单（`tools.restrict`）→ 沙箱策略 → 危险工具审批。
3. **群内文本不可信**：群消息是讨论内容，不是操作指令。

## 档位

| 档位 | 识别方式 | 会话键 | 工具范围 |
|---|---|---|---|
| `owner` | `sender_id ∈ admins` 且私聊 | `dm:<qq>` | 不限制 |
| `owner-group` | 管理员在群里（且通过准入） | `group:<gid>` | 联网 + 发消息 + 记忆 + 日报 + 状态（**无文件、无 shell**） |
| `member` | 非管理员私聊 | `dm:<qq>` | 联网 + 发消息 + 记忆卡 |
| `member-group` | 非管理员在群里 | `group:<gid>` | 联网 + 发消息 + 记忆卡 + 日报 |

「陌生人」不是档位，而是**准入结果**：非管理员私聊时按 `access.strangerPolicy` 决定忽略 / 回一句 / 拉黑。

## 准入（admit）

一条消息进入模型前要过四关：

1. 命中 `access.blockedWords` → 丢弃
2. 私聊且非管理员 → 按 `strangerPolicy` 处理
3. 群聊且不满足 `groupMode`（白名单/黑名单/全部）→ 丢弃
4. 群聊且 `mentionOnly` 为真但没有 @ 机器人 → 丢弃

## 允许矩阵（当前实现）

| 工具 | owner | owner-group | member | member-group |
|---|---|---|---|---|
| `read` / `glob` / `grep` / `read_image` | ✅ | ❌ | ❌ | ❌ |
| `write` / `edit` / `pwsh` / `plugin_manager` | ✅ | ❌ | ❌ | ❌ |
| `web_search` / `web_fetch` | ✅ | ✅ | ✅ | ✅ |
| `qq_send`（附件仅 owner） | ✅ | ✅ | ✅ | ✅ |
| `qq_history` | ✅ | ✅ | ❌ | ❌ |
| `memory_card_get` / `memory_note` / `memory_persona_set` / `memory_card_clear` / `memory_card_send` | ✅ | ✅ | ✅ | ✅ |
| `group_digest` | ✅ | ✅ | ❌ | ✅ |
| `qq_status` | ✅ | ✅ | ❌ | ❌ |

记忆类工具**永远只作用于调用者自己**：QQ 号从会话解析，不接受参数，群里也没法改别人的卡。

## 审批

管理员私聊里执行 `write` / `edit` / `pwsh` / `plugin_manager` 前，桥会挂起并在 QQ 里要求 `/yes` 确认（默认 60 秒有效）。群档位没有这些工具，所以不存在"群里骗审批"的路径。

## 配额

- 每人每天 `limits.memberDaily` 次（0 = 不限）
- 每群每天 `limits.groupDaily` 次
- 每人每分钟 `limits.userPerMinute` 次
- 管理员不受配额限制

计数是内存态的，重启清零；按北京时间自然日滚动。

## 面板

`/dsh-to-qq/api/*` 只接受**本机回环地址 + 同源 Origin** 的请求，跨域一律 403。这是唯一能改配置的入口，QQ 侧没有任何改配置能力。

## 为什么群档连管理员也不给文件权限

群里任何人的文本都会进入上下文。如果 `owner-group` 保留 `read`，攻击链就是：

```
群成员埋一句诱导文本 → 管理员 @ 机器人 → 模型带着全盘读权限处理这段文本
```

`read` 看起来无害，实际等于"能在回复里复述磁盘上任何文件"。所以群档（包括管理员在群里）一律没有文件与 shell 工具；需要动本机就回私聊。

## 审批只批"这一条"

`/yes` 批准的是**一次具体调用**（工具名 + 参数签名），不是整个工具：

| 请求 | `/yes` 后 |
|---|---|
| `pwsh { command: "git status" }` | 仅这条命令可执行 |
| 同一工具换参数 `rm -rf /` | 仍需重新 `/yes` |
| 超过 5 分钟未批准 | 请求失效，模型要重新发起 |

## 事件身份

身份只来自 OneBot 的 `sender_id` / `self_id`。插件会固定机器人账号（`connection.botUin`，或从第一条事件学习后锁定），`self_id` 不符的事件直接丢弃——这是本机端口被抢占时唯一的兜底。

## 群共用一份上下文

一个群只有一个会话，`groupHistory` 条最近消息会被带进每次提问。这意味着：

- 群里任何人都可能让机器人"总结一下大家说过什么"——这些内容本来就对群成员可见，但新入群的人没看到
- 提示词里加了一条硬规则：**不要复述、总结、转述或引用其他成员的消息**，被问到时只回答本轮内容
- 想彻底避免，就把 `conversation.groupHistory` 设成 `1`（只带当前这条），或把 `conversation.groupPrivacy` 关掉再自行处理

私聊与群聊、不同群之间的会话完全隔离，跨场景看不到彼此内容。

## 敏感词的作用范围

`access.blockedWords` 会扫描**合并后的全部文本**：正文、引用、转发内容、语音转写、文件名。命中即静默丢弃（计数里记 `ignored`）。

图片内容本身无法做关键词匹配，需要的话只能靠群档不提供文件/命令权限来兜底。
