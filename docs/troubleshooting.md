# 排障

按"症状 → 原因 → 处理"组织，全部来自真实踩过的坑。

## 插件没加载 / 设置页空白

**症状**：`qq_status` 工具不存在，面板接口 404，设置页报渲染错误。

**原因**：Host 半边在启动时抛错，DSH 会把整个 entry 标为未激活。常见是代码里的前置引用（TDZ）。

**处理**：
1. 看 DSH 启动日志里是否有 `ReferenceError`
2. 安装新版本后**必须重启 DSH**，热重载不会重新求值失败的模块
3. 开发时先跑 `npm run smoke`——它会真调 `apply()`，能抓住这类错误

## 设置页 403 / 打不开

**症状**：`/dsh-to-qq/api/*` 返回 403。

**原因**：面板只允许**本机回环 + 同源**请求。

**处理**：从 `http://127.0.0.1:<端口>` 打开，不要用局域网 IP 或反代域名；也不要在别的网页里 fetch 它。

## `transport online` 但发消息无反应

排查顺序：

1. **群没 @**：默认 `access.mentionOnly: true`，群里必须 @ 机器人。
2. **群不在白名单**：`access.groupMode` 默认 `whitelist`，把群号加进 `access.groups`。
3. **QQ 号不是管理员**：私聊要进 `access.admins`；否则走陌生人策略（默认静默忽略）。
4. **OneBot token 没填**：`connection.token` 为空时状态会是 `no-token`。
5. **SnowLuma 没加载 hook**：WebUI 里重新注入。

## `llm-deepseek: no API key for provider route "deepseek-official"`

**症状**：补印象 / 翻译失败，或对话报这个错。

**原因**：DSH 的模型目录里 `default` 指向 `deepseek-official`，但本机只登录了 `deepseek-account`（账号路由），前者没有 API key。

**处理**：升级到 0.33.4 之后插件会自动挑可用的路由；仍失败时在 **设置 → 模型** 里把「翻译与印象整理」显式选成可用服务商。

## 语音消息只回"语音转写不可用"

**症状**：收到语音，但内容没转出来。

**原因**（按概率）：
1. QQ 语音转文字是**异步推送**的，第一次调用可能只发起请求，20 秒内没等回结果
2. 语音刚到达时媒体缓存还没就绪，会返回 `ptt translate failed: error=9`
3. 消息已过期，QQ 侧不再保留

**处理**：插件会重试一次；仍然失败时，让对方重发一条，或改用文字。`qq_status` 的日志里能看到具体 `wording`。

## 图片变成了 `[图片]` 占位

**原因**：

1. 图片超过 8MB 被丢弃（避免把巨大的 base64 塞进 prompt）
2. 下载失败（URL 过期 / 网络）
3. GIF 帧图合成失败

**处理**：看日志里的 `image skipped: …`；让对方重发或压缩后再发。

## 合并转发只有文字、没有图

**原因**：早期版本只展开一层且不下载图片。

**处理**：0.36.0 之后支持两层展开与图片下载。引用转发也支持（0.36.2）。若仍为空，多半是转发内容已过期，QQ 侧取不到了。


## 识图/日报报 `no API key for provider route "deepseek-official"`

**原因**：新会话默认继承部署默认模型，而默认路由可能没有配 key（例如 `deepseek-official`）。

**处理**：插件在创建会话时会用 `models.owner`（未配置则按"已配置 → 可路由默认 → 第一个 account 提供方"）**显式选中一个可路由模型**；识图请求还会在发送前再选一次。若仍报错，说明没有任何可路由模型：到设置 → 模型里选一个带 key 的路由保存。

## 表情包发不出来 / 模型从不发表情

**原因**：

1. 没同步过收藏表情（设置 → 表情 → 点「识图」）
2. 表情发出去是一张图片 → 模型用了 `qq_send` 而不是 `sticker_send`
3. 配额用尽（默认每会话每小时 3 张）
4. 表情没有描述，模型认不出它适合什么场合

**处理**：见 [表情包库](stickers.md) 的排障表。

## 卡片渲染失败

**症状**：`/记忆卡` 或 `/日报` 没出图，退回文字。

**原因**：PowerShell 脚本执行失败（GDI+ 不可用、字体缺失、临时目录不可写）。

**处理**：
1. 确认是 Windows 且 `powershell.exe` 可执行
2. 看日志里的 `render failed: …`
3. 临时目录被安全软件锁住时，重启一次可恢复

## 面板显示"上次补：…"但记忆卡还是空的

**原因**：补印象有门槛——每人至少 **300 字有效内容 + 8 条不同发言**（首次补历史），日常整理要 100 条新消息且 800 字。

**处理**：让人多聊几句；或 `/记忆卡 <QQ>` 看当前内容。日志里 `impression summary produced no bullets` 表示模型输出格式不对，插件会自动重试一次。

## 回复很慢或排队

- 默认并发 2（`limits.concurrency`），排队上限 10
- 单轮超时 180 秒（`limits.turnTimeoutMs`），超时释放槽位
- 回答前有 2 秒基础延迟 + 随机抖动（`limits.replyDelayMs` / `jitterMs`）

调这些值在 **设置 → 权限**。

## 数据越来越大

- `archive.retentionDays` 默认 30 天，插件每 6 小时自动清理数据库行与 `media/` 文件
- 想立刻清：设置 → 档案 → 立即清理
- 想永久保留：设为 0（不推荐，档案会无限增长）

## 需要提供什么信息才能定位问题

1. `qq_status` 的完整输出
2. 出问题那条消息的时间与场景（私聊 / 群号）
3. `%USERPROFILE%\.dsh\dsh-to-qq\` 下 `config.json`（**先删掉 token**）
4. DSH 启动日志里与 `dsh-to-qq` 相关的行

## 语音只有 QQ 原生转写

`qq_status` 里出现 `speech: unavailable (QQ 原生转写 only)` 表示：

- 没有安装 Host 的 `speechToText` 提供方
- 也没有配置 `voice.command`

此时只有 QQ 自带的语音转文字可用（`fetch_ptt_text`）。想加本地兜底，二选一：

| 方式 | 配置 |
|---|---|
| Host 语音服务 | 安装提供 `speechToText` 的插件，`voice.qqAsr: false` 可强制走它 |
| 外部命令 | `voice.command`，例如 `whisper -f {input} -l {language} -otxt -of {output}` |

状态行会显示当前生效的组合，不用猜。

## 敏感词没拦住

`access.blockedWords` 现在会扫描正文、引用、转发、语音转写与文件名，命中后静默丢弃并计入 `ignored`。如果仍看到漏网：

1. 确认词没有多余空格（匹配是区分大小写的子串）
2. 图片里的文字不会被 OCR，无法拦截
3. 私聊管理员的消息同样受敏感词约束

## DSH 直接退出（窗口消失）

插件里的未捕获异常会让 **DSH 主进程退出**，看起来就是"闪退"。先看崩溃日志：

```
%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-*.log
```

里面会给出出错的文件、行号和调用栈（例如某个事件处理器里的变量未定义）。这类问题只能在下次启动时修复，所以：

1. 记下栈里的文件与行号
2. 重新打包安装后再重启
3. 如果日志指向 `dsh-to-qq`，把那段贴出来即可
