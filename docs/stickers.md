# 表情包库

把 QQ 账号自己的「收藏表情」变成机器人可用的表情包：模型在合适的时候挑一张发出去，QQ 客户端显示为**动画表情**，而不是一张图片。

设置页有一个独立的 **表情** 页签，用来识别、预览和手工修正。

## 界面上有什么

```
收藏表情包 42/100                                  [识图]
┌────┐┌────┐┌────┐┌────┐┌────┐┌────┐
│ 🐳 ││ 🐱 ││ 🐶 ││ 🐼 ││ …  ││ …  │        ← 缩略图；未识别的半透明
└────┘└────┘└────┘└────┘└────┘└────┘
────────────────────────────────────────────
┌──────────┐  编号  [1e5442      ]
│  大图预览 │  分类  [卖萌        ]
│          │  备注  [鲸鱼娘女仆装，适合卖萌]
└──────────┘  [保存]   模型识别
```

- **计数**：`已识别 / 总数`，一眼看出还有多少没读
- **识图**：只处理**没读过**的，不会重复识别（`stickers.describeBatch` 控制每次识别上限，默认 20；预览每轮最多下 40 张，避免一次拉几百 MB）
- **缩略图**：点击选中，未识别的半透明显示
- **大图预览 + 三个可编辑字段**
  - **编号**：模型调用 `sticker_send` 时用的 handle，默认是 md5 前 6 位，可改成 `1`、`笑` 等；**不允许重复**
  - **分类**：自由填，比如 `卖萌` / `无语` / `梗图`，会显示在提示里
  - **备注**：一句话描述，模型据此判断语境；识图不准时手改，**手改后再识图不会被覆盖**
- 保存后下一轮对话生效，不需要重启

## 它怎么工作

```
收藏表情 ──fetch_custom_face_detail──▶ stickers.json（md5 / id / 预览图）
   启动 60 秒后自动同步，之后每 12 小时
        │
        ├─ 预览图下载后缩到 160px 存到 media/stickers/<md5>.png（QQ 原图常有 2.8 MB，缩完约 70 KB）
        ├─ QQ 自带描述（只有约 3% 有）直接算已读
        └─ 其余交给视觉模型：按「画面|情绪|用途」三段分析，写完标记已读
        ▼
提示里注入索引（默认 24 条）：`1e5442〔卖萌〕鲸鱼娘女仆装，适合卖萌`
        ▼
模型判断语境 → sticker_send（编号或关键词）
        ▼
send_custom_face ──▶ QQ 显示为【动画表情】
```

**为什么不用 `mface` 段**：自定义表情手工拼 `mface` 会被 QQ 拒绝（实测 `result=-13100`）。SnowLuma 的 `send_custom_face` 内部发的是 `image + sub_type:1 + summary:"[动画表情]"`，这才是 QQ 认的形状。

## 什么时候不发

两道闸门：

**模型判断**（提示词里写死）：

> 只在语境真的合适时发；对方明确表示收/不收，或正在严肃讨论时不要发；一轮最多一个。

**对方说过不收**（每个会话单独记，持久化）：

| 说法 | 效果 |
|---|---|
| 「别发表情包了」「以后不要用表情了」 | 该会话**关闭表情**，提示里改为「对方说过不想收表情，本轮不要发」，工具直接拒绝 |
| 「可以发表情了」「发表情吧」 | 恢复 |
| 其他会话 | 互不影响 |

识别是关键词级的（私聊、群聊都生效），不会因为一句「这个表情包不错」就误关。

## 配额

桥这一层只兜底模型不该负责的事：

| 限制 | 默认值 | 配置键 |
|---|---|---|
| 同一会话每小时最多 | 3 张 | `stickers.perHourPerScene` |
| 一轮提示里列出的表情数 | 24 张 | `stickers.inPrompt` |
| 总开关 | 开 | `stickers.enabled` |

超过配额时工具**返回错误而不是静默丢弃**，模型能据此改回文字。

## 工具

`sticker_send`：

| 参数 | 说明 |
|---|---|
| `sticker` | 编号（`1e5442` / 手改的 `7`），或描述/分类关键词（如「笑」「卖萌」） |

四档权限都可用：表情包不涉及本机操作，群里的人也能让机器人发表情。


## 顺带：QQ 自带表情（小黄脸）

收藏表情是账号资源，要同步、要识别；**QQ 自带表情不需要任何准备**：`face` 段带一个整数 id 就能发。

实测（发给管理员私聊）：

```
face 14  -> ok   face 179 -> ok   face 178 -> ok   face 13 -> ok
```

所以桥额外提供一个 `emoji_send` 工具，参数是名字或数字 id，内置一份常用清单：

| 情绪 | 表情 |
|---|---|
| 开心 | 呲牙13 偷笑20 调皮12 得意4 |
| 无语 | 白眼22 抠鼻98 晕34 |
| 感谢 | 鼓掌99 强136 抱拳140 玫瑰120 |
| 安慰 | 拥抱135 亲亲109 爱心123 |
| 难过 | 流泪5 大哭9 委屈106 快哭了107 |
| 收尾 | 再见39 嘘33 |
| 反讽 | 狗头179 |

规则和表情包一致：语境合适才发、一轮最多一个、对方说过不收就不发（共用同一份免打扰记录）。

**能力边界**：

| 类型 | 能否发 | 原因 |
|---|---|---|
| 收藏表情（自定义） | ✅ `send_custom_face` | 需要账号收藏，走 `image + sub_type:1` |
| QQ 自带小黄脸 | ✅ `face` 段 | 只认 id，零准备 |
| 商城表情（mface） | ❌ | 需要 `emoji_package_id` + `key`，OneBot 转发拿不到完整三元组 |
| 别人的表情包 | ❌ | 同上，属于商城资源 |


## 识图分析怎么给的

模型不是被要求"描述这张图"，而是被要求**为将来挑选服务**，输出一行三段：

```
猫猫敲键盘|无语|对方抱怨加班时
```

| 段 | 用途 | 长度 |
|---|---|---|
| 画面 | 主体 + 关键动作；图里有字先写字 | ≤ 14 字 |
| 情绪 | 从固定清单里选：开心 / 卖萌 / 无语 / 嘲讽 / 震惊 / 难过 / 鼓励 / 感谢 / 疑问 / 敷衍 / 其他 | 一个词 |
| 用途 | 什么情况下该发它 | ≤ 16 字 |

解析后：**情绪**进 `分类` 字段，**画面 + 用途**合成 `备注`，于是提示里变成：

```
- 1e5442〔无语〕猫猫敲键盘，对方抱怨加班时
```

模型挑表情时看到的是"什么时候发"，不是"图里有什么"——这才是能自主判断的索引。

**重新分析**：页签上除了「识图」还有一个「重识别」，会把**没手改过**的表情全部重新分析一遍（每轮最多 20 张）。手改过的永远跳过，不会被覆盖。

**情绪同义词**：模型偶尔会写「嘲讽/开心」，取第一个（嘲讽）。

## 已知限制

1. **识别要花模型调用**：100 张首次约需 5 轮（每轮 20 张），可调大 `describeBatch` 加速。
2. **描述截断到 60 字**、编号 12 字、分类 12 字，太长会挤占提示预算。
3. **表情是账号级共享的**：小号收藏的表情就是全部库存，不按群区分。
4. **预览图可能过期**：来自 QQ 的 URL，长期不用可能失效，重新同步会补下。
5. **手改优先**：一旦手动编辑过，自动识图不会再覆盖备注（只会把它标成已读）。

## 排障

| 现象 | 处理 |
|---|---|
| 计数是 `0/0` | 点「识图」；确认 SnowLuma 在线、`fetch_custom_face_detail` 可用 |
| 缩略图是「…」占位 | 预览还没下载下来（每轮最多 40 张），再点一次「识图」；看日志 `sticker media failed` |
| 识别数量不涨 | 先看是不是全读完了；模型路由不可用时日志会有 `sticker describe failed` |
| 模型从不发表情 | 检查 `stickers.enabled`、提示里有没有索引（`qq_status` 的 stickers 行）、是否被配额或「不要表情」挡住 |
| 发出去是一张图片 | 走的是 `qq_send` 而不是 `sticker_send`，让模型改用后者 |
| 之前说过不要表情，现在想恢复 | 在同一个会话里说「可以发表情了」 |
