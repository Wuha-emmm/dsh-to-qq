# 剧本：三角洲行动 · 特勤处四工位（按需下单 / 重造上一批）

> 环境假设：屏幕 2560×1440、游戏全屏、WeGame 已登录（账号「哞哈」）。
> 坐标系：全屏绝对像素坐标（左上角 0,0）。分辨率变了，全部坐标等比缩放。
> 版本：**v3 · 2026-11-01** —— v1 当晚实操；v2 加入工位状态判断与决策表；v3 合入切前台、模式页、逐动作执行等实测坑。

## 0. 前置与铁律

1. **权限**：让用户发 `/yes!` 或 `/全放行`（默认 15 分钟有效）。
2. **一次只做一个动作，做完立刻截图确认**。禁止批量连点——2026-11-01 那次批量点击直接导致「防具台领取失败」且无法定位错在哪一步。
3. **先领、再造**。工位没空出来就下不了单。
4. 时间显示是 `时:分:秒`：`29:56:53` = 29 小时 56 分，**不是分钟**。
5. **花钱确认**：点绿色总价按钮付款前，把「工位 + 物品 + 总价」报给用户；给了总额授权按总额执行，超了就停。
6. **决策必须落表**：每个工位都要按 §4 给结论并写进 §4.3；没写记录 = 这轮没执行完。
7. 截图只在需要判断"下一步点哪"时读；发图给人不要附带解释。

## 2. 切前台 + 进大厅

### 2.1 切前台（第一次必踩）

普通 `SetForegroundWindow` 会被系统前台锁挡掉，前台仍是 QQ。必须先 ALT 轻点一下：

```powershell
[F]::keybd_event(0x12,0,0,[IntPtr]::Zero)   # ALT 下
[F]::keybd_event(0x12,0,2,[IntPtr]::Zero)   # ALT 上
[void][F]::ShowWindow($h,9)                 # SW_RESTORE
[void][F]::SetForegroundWindow($h)
```

判据：`GetForegroundWindow()` 的 pid = 游戏 pid。**切不过去就别往下点**，点了也是点在 QQ 上。

### 2.2 模式页（最容易走错）

绿色「前往游玩」跟着当前选中的模式走，位置不固定。

| 情况 | 正确操作 |
|---|---|
| 页面是「烽火地带」 | 点「前往游玩」(460, 1236) |
| 页面是其它模式（黑潮爆破 / 全面战场 / 红鼠窝） | **别点它的「前往游玩」**（会进「进入游戏」房间面板，再点真开一局）。按 **Esc** → 点左下「烽火地带」卡片 **(345, 1244)** → 再点它自己的「前往游玩」 |

### 2.3 进大厅

1. 赛季宣传页 → 按 **空格** 3 次（间隔 3 秒），比点「继续」稳。
2. 大厅（战术部门 / 医疗部门 / 研发部门 那屏）→ 按 **Tab** (0x09)。
3. 进入「开始游戏」界面（顶部 仓库 / 特战干员 / 特勤处 / 改枪台）。

## 3. 到特勤处并判断四个工位状态

| 步骤 | 动作 |
|---|---|
| 3.1 | 点顶部「特勤处」**(1121, 77)**。右边「改枪台」是 (1250, 78)，点错会进改枪台 |
| 3.2 | 截图确认标题是「特勤处」，四个工位都可见 |
| 3.3 | 逐格判状态（见下表），判完四个才进 §4 |

### 3.3 状态识别

| 状态 | 画面特征 | 判定 |
|---|---|---|
| 空闲 | 空白框 +「＋」+「空闲中」 | 可下单 |
| 正在造 | 成品图 + 剩余时间（如 `07:59:07`）+「中止」 | 本轮跳过，**不中止不插队** |
| 已完工 | 成品图 + 黄色「!」角标 + **没有**剩余时间 | 先领取，再决定重造 |
| 认不出 | 模糊 / 被遮挡 / UI 改版 | 停下问用户，禁止猜 |

要点：逐格判定，不拿一格的结论推断另一格；判完立刻记到 §4.3。

## 4. 每个工位造什么（决策）

### 4.1 三种输入

1. **用户指定**：`技术中心=某物品`……可以只指定一部分。
2. **上一批（默认）**：该工位「已完工」那件成品同名物品；没有可领成品时，查 §4.3 里该工位上一轮实际下单的物品。
3. **都没有**：跳过。

### 4.2 决策表

| 工位状态 | 用户指定？ | 动作 | 失败时 |
|---|---|---|---|
| 已完工 | 有 | 领取 → 按指定下单 | 领取失败则记原因并跳过 |
| 已完工 | 无 | 领取 → 记下成品名 → 同名重造 | 领取失败则记原因并跳过 |
| 正在造 | 任意 | 跳过 | — |
| 空闲 | 有 | 按指定下单 | 找不到图纸则截图问用户 |
| 空闲 | 无，有上一批 | 按 §4.3 记录的上一轮物品下单 | 记录缺失则跳过 |
| 空闲 | 无，无记录 | 跳过 | — |
| 认不出 | 任意 | 跳过并记录 | — |

判定顺序：**先看状态 → 再看有没有指定 → 最后用「上一批」兜底**。正在造的工位一律不碰。

## 5. 单工位操作

### 5.1 领取（状态 = 已完工）

1. 点工位卡片的**图片中心**（工作台 (835, 562)、制药台 (388, 989)、防具台 (836, 989)）。
2. 弹「获得奖励」→ 按 **空格** 或点「继续」。
3. 截图确认卡片变回「空闲中」才算领到。
4. **记下成品名**，这是下一步「同名重造」的唯一依据。

失败分支：点不动 / 置灰 / 仓库满 / 报错 → 记录原因，**跳过该工位，最多再试一次**，不反复点。

**已知未解决问题**：2026-11-01 晚，防具台的「精英防弹背心」点图片、点标题、双击都无反应，同一批的另外三件正常。遇到就记为「领取失败」，交给人处理；「进 3D 车间点机器领」这条路尚未验证。

### 5.2 下单（状态 = 空闲）

1. 点「＋」→ 图纸列表（左侧带名称，按价格从高到低）。
2. 选目标：名称必须与决策表完全一致，点错就是造错东西，可能需下滚（§5.3）。
3. 右侧出现详情（参考价、仓库数量、材料槽）。
4. 材料不足时点「一键补齐」**(2244, 1290)**。
5. 弹「一键补齐清单」→ **先把总价报给用户** → 点绿色总价 **(1281, 989)** 付款。
6. 材料变 `n/n`，右下按钮变「生产」→ 点 **(2244, 1270)**。
7. 截图确认出现「剩余时间」且按钮变「中止」。
8. 按 **Esc**（必要时两次）回特勤处，再进下一个工位。

### 5.3 图纸位置（仅「上一批」这几样有固定参考）

| 工位 | 生产物 | 定位 |
|---|---|---|
| 技术中心 | M14射手步枪 | 下滚 10～11 格，在 RM277突击步枪 上一行 |
| 工作台 | 7.62x51mm M62 ×120 | 下滚 5 格，点 (450, 1118) |
| 制药台 | 高级头盔维修组合 | **不用滚**，第 2 行 (577, 447)；第 1 行是「高级护甲维修组合」，别点错 |
| 防具台 | 精英防弹背心 | 下滚 9 格，在 Hvk-2防弹衣 下一行 |

用户指定了别的物品时，上面滚动次数**不适用**：按名称现找，滚到列表头再逐段下滚，找不到就截图问。

## 6. 技术细节

### 6.1 滚轮

```powershell
$neg = [uint32]4294967176   # -120，向下滚一格
1..5 | ForEach-Object { [M]::mouse_event(0x0800,0,0,$neg,[IntPtr]::Zero); Start-Sleep -Milliseconds 150 }
```

先把鼠标移到列表区（如 (450, 900)）再滚。

### 6.2 点击

```powershell
[void][M]::SetCursorPos($x,$y); Start-Sleep -Milliseconds 300
[M]::mouse_event(0x0002,0,0,0,[IntPtr]::Zero); Start-Sleep -Milliseconds 90
[M]::mouse_event(0x0004,0,0,0,[IntPtr]::Zero)
```

### 6.3 按键

```powershell
$vk = 0x20  # 空格 0x20；Tab 0x09；Esc 0x1B
[M]::keybd_event($vk,0,0,[IntPtr]::Zero); Start-Sleep -Milliseconds 80
[M]::keybd_event($vk,0,2,[IntPtr]::Zero)   # 0x2 = KEYEVENTF_KEYUP
```

### 6.4 截图

```powershell
Add-Type -AssemblyName System.Windows.Forms,System.Drawing
$b = [System.Windows.Forms.SystemInformation]::VirtualScreen
$bmp = New-Object System.Drawing.Bitmap $b.Width, $b.Height
$g = [System.Drawing.Graphics]::FromImage($bmp)
$g.CopyFromScreen($b.X,$b.Y,0,0,$bmp.Size)
$bmp.Save("E:\DSH-to-QQ\df-$(Get-Date -Format HHmmss).png", [System.Drawing.Imaging.ImageFormat]::Png)
$g.Dispose(); $bmp.Dispose()
```

### 6.5 PowerShell 两个坑

- `Add-Type` 定义的 C# 类型**不跨命令保留**，每条 pwsh 都要重新 `Add-Type`，或整套写成 `.ps1` 一次跑完。
- 函数调用不加括号：`C6 835 562`；写成 `S6()` 会解析报错。

## 7. 安全与风险

- 会**花游戏币**买材料（上次四单约 47 万）。每单付款前确认总价，超授权就停。
- 点错工位就是造错东西，几乎不能撤，每步截图确认。
- **跳过优先于硬点**：状态认不出、领取失败、材料不够、图纸找不到——一律跳过并记录，不猜、重试不超过一次。
- 游戏更新后 UI 会变，坐标会失效：先截图，按画面重新定位，别硬点。

## 8. 触发方式

> **重造上一批**：「按三角洲剧本重造这批」→ 全部工位走「已完工 → 领取 → 同名重造」，没成品的跳过。
>
> **按需指定**：「按三角洲剧本：技术中心造 XX，工作台造 YY」→ 指定的按指定造，没指定的按「上一批」，都没有就跳过。

执行顺序固定：§1 准备 → §2 切前台+进大厅 → §3 判状态 → §4 决策 → §5 逐工位操作 → 按 §4.3 汇报（状态、物品、花费、剩余时间、跳过原因）。
